# Feature Specification: 宠物语音改成本地预录音频优先播放

**Feature**: `prerecorded-voice-audio`  **Created**: 2026-11-11  **Status**: Draft
**Input**: 宠物语音改成本地预录音频优先播放。用 edge-tts 批量预生成全部台词音频，放到 public/ 下由渲染进程 Audio 播放；台词 id 化，文本只存一份；音频文件名带引擎前缀；生成脚本幂等、重试、覆盖率校验；本地命中优先、未命中回退现有 TTS；清理死代码 attributeDialogues；收编散落各处的硬编码台词。用户明确要求脚本和音频都提交到 git。

## User Scenarios

### User Story 1 - 宠物说话从本地音频秒出，不再依赖网络 (Priority: P1)

宠物触发任何一句台词时，若该台词已有预录音频，直接播放本地文件，无网络请求、无子进程、无 Python 环境依赖；音频播完或气泡到时后正确停止。

**覆盖 FR**: FR-001, FR-002, FR-009, FR-010, FR-011

**为何这个优先级**: 解决"TTS 转换失败"和"音质差"两个原始痛点；没有这一条，整个需求没有价值。

**独立测试**: 断网启动应用，点击宠物直到触发一句已有音频的台词，应能正常听到语音；观察控制台无 edge-tts 子进程、无网络请求。

**验收场景**:
1. **Given** 应用已启动且语音开关打开，**When** 宠物触发一句存在预录音频的台词，**Then** 该台词在 200ms 内开始播放音频，且不启动 edge-tts 子进程
2. **Given** 一句台词正在播放，**When** 用户点击宠物触发新台词，**Then** 旧音频立即停止，新音频开始播放，不出现两路声音叠加
3. **Given** 用户关闭语音开关，**When** 宠物触发台词，**Then** 只显示气泡文字，不播放任何音频
4. **Given** 应用处于离线状态，**When** 触发已有音频的台词，**Then** 语音正常播放，不出现任何网络相关报错

---

### User Story 2 - 台词只有一份文本，且每句有稳定 id (Priority: P1)

所有台词集中在一个数据模块，同一句文本在全项目只出现一次（跨分组复用时共享同一条目）；每条台词有不受数组顺序和文本改动影响的稳定 id，音频文件按 id 命名。

**覆盖 FR**: FR-003, FR-004, FR-005, FR-006, FR-012, FR-013, FR-017

**为何这个优先级**: 用户明确提出"文本只存一份、不要多处重复"。这是后续所有音频生成与播放的基础，id 不稳定会导致音频错位。

**独立测试**: 在数据模块中搜索同一句文本，应只命中一处；在任意分组中间插入一条新台词，已有台词的 id 与音频文件名保持不变。

**验收场景**:
1. **Given** 台词数据模块，**When** 全项目 grep 某句台词文本，**Then** 只在数据模块命中一次
2. **Given** 某分组已有 20 条台词，**When** 在数组开头插入一条新台词，**Then** 原有 20 条台词的 id 和音频文件名全部不变
3. **Given** 某句台词在 jumping 和 swinging 两个分组复用，**When** 查看数据，**Then** 两处引用同一个台词条目、只有一个 id、只生成一个音频文件
4. **Given** 修改某句台词文案，**When** 运行音频生成脚本，**Then** 该台词获得新 id 并生成新音频，其余台词音频不重新生成

---

### User Story 3 - 一句话就能补齐或重新生成音频 (Priority: P2)

维护者新增台词或更换语音引擎时，运行一条命令即可生成缺失音频、重试失败项、并报告覆盖率；脚本可重复运行不产生重复劳动。

**覆盖 FR**: FR-007, FR-008, FR-014, FR-015

**为何这个优先级**: 台词会持续增补，没有这条维护成本会失控。但它在首次交付后才会被用到，所以低于 P1。

**独立测试**: 重复运行生成脚本两次，第二次应直接跳过已有文件；故意删除一个音频文件后运行，只重新生成被删的那一个。

**验收场景**:
1. **Given** 全部音频已生成，**When** 再次运行生成脚本，**Then** 不发起任何 TTS 请求，全部跳过
2. **Given** 新增了 3 条台词，**When** 运行生成脚本，**Then** 只为这 3 条生成音频，其余文件不动
3. **Given** 某条台词生成时网络失败，**When** 脚本重试 3 次仍失败，**Then** 脚本继续处理后续台词，结束时列出失败清单并以非零退出码结束
4. **Given** 台词数据中有 id 但缺少音频文件，**When** 运行覆盖率校验，**Then** 输出缺失清单并标明缺失数量

---

### User Story 4 - 语音设置面板如实反映本地音频的能力边界 (Priority: P3)

用户能知道当前使用的是预录语音还是 TTS 回退，并且明白哪些调节项对预录语音不起作用。

**覆盖 FR**: FR-011, FR-016

**为何这个优先级**: 属于体验完善项，不影响核心播放链路，但不能不说清楚，否则用户会以为语速滑块坏了。

**独立测试**: 打开语音设置面板，观察语速/音调滑块在预录语音播放时的状态与说明文案。

**验收场景**:
1. **Given** 打开语音设置面板，**When** 查看语速与音调滑块，**Then** 显示明确说明表示这两个设置只对 TTS 回退生效、对预录语音无效
2. **Given** 语音引擎设置为 Edge TTS 且未安装 edge-tts，**When** 触发一句没有预录音频的台词，**Then** 自动回退到浏览器 TTS 并正常发声，不弹错误对话框

### Edge Cases

- 台词文本中包含中英混杂内容（如 `Zzz...`、`Bug在哪里？`、`Stack Overflow救我！`、`NullPointerException！`、`等级 up up！`、`身上 dusty...` 等 18 条），TTS 会逐字母朗读或读错，需为这些条目提供生成用的替代文本，同时气泡显示的仍是原文
- 不含可朗读内容的台词（如 `？？？`）不生成音频，播放时走回退路径，覆盖率校验中单独归类为已豁免（见 FR-017）
- 音频文件存在但内容损坏或为 0 字节时，播放应失败并回退 TTS，而不是静默无声
- 用户快速连续触发多句台词（如连续点击宠物）时的音频打断行为
- 应用从开发模式（vite dev server）切换到打包模式（file:// 加载）时音频路径的差异
- 音频总体积对安装包体积的影响
- 预录音频与 TTS 回退混用时，音量设置是否一致
- 更换语音引擎（如从晓伊换成另一音色）后，旧引擎目录的音频是否保留

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 在播放任何台词前，先判断该台词是否存在对应的预录音频文件
- **FR-002**: 系统 MUST 优先播放预录音频，仅在无可用音频时回退到现有 TTS 引擎（浏览器 speechSynthesis / Edge TTS）
- **FR-003**: 系统 MUST 为每条台词分配稳定 id；id 不得由数组下标推导，也不得由文本内容 hash 推导。id MUST 由仓库内维护的台账文件（文本 → id 的映射）统一分配：新增文本分配新 id；文本修改视为一条新台词、分配新 id；旧 id 保留但不回收
- **FR-004**: 同一句文本 MUST 在全项目只存储一份，跨分组复用时引用同一条目、共用同一个 id 和音频文件
- **FR-005**: 台词 id MUST 能体现其所属分组（状态 / 天气 / 心情 / 属性等），便于人工核对音频归属
- **FR-006**: 台词数据结构 MUST 支持为单条台词指定"生成用文本"覆写，该覆写只影响音频生成，不影响气泡显示
- **FR-007**: 系统 MUST 提供批量生成音频的 Node 脚本并以 npm script 暴露，具备：跳过已存在且未变化的条目、失败重试（3 次）、失败项汇总报告、非零退出码表示有失败
- **FR-008**: 系统 MUST 提供覆盖率校验能力，能列出"台词有 id 但缺音频"的条目；覆盖率不足 MUST 只产生警告，不得阻塞 `npm run build`
- **FR-009**: 音频文件 MUST 按"引擎与音色前缀作为目录名 + id 作为文件名"的组织方式存放（`public/audio/<engine>@<voice>/<id>.mp3`），使更换引擎或音色时新旧音频可以并存
- **FR-010**: 系统 MUST 在气泡隐藏时停止正在播放的音频；气泡显示时长 MUST 与音频实际时长协调（取固定下限与实际音频时长的较大者），不得在语音未播完时截断
- **FR-011**: 语音设置面板 MUST 如实说明语速/音调设置对预录语音不生效，并 MUST 保持浏览器 TTS 回退路径可用
- **FR-012**: 散落在问候语、LLM 服务、天气背景等处的硬编码台词 MUST 收编进统一的台词数据模块。状态特效徽章上的装饰性文字（如特效里的"嘿嘿~""阿嚏!"）MUST NOT 纳入台词体系——它们只做视觉展示、从不发声
- **FR-013**: 全项目无引用的 `attributeDialogues` 数据 MUST 删除
- **FR-014**: 批量生成脚本与生成的音频文件 MUST 提交进 git 仓库，使其他使用者克隆后即可直接使用，无需自行生成
- **FR-015**: 系统 MUST 在生成音频的同时产出一份静态音频清单并提交进仓库，供运行时 O(1) 判断某条台词是否存在本地音频；运行时 MUST NOT 依赖网络请求或文件存在性探测来判断音频可用性
- **FR-016**: 系统 MUST 彻底移除基于 edge-tts 子进程的 Edge TTS 播放路径，包括主进程播放模块、IPC 通道、preload 暴露接口与语音面板中的引擎切换项；语音回退路径 MUST 仅保留浏览器 TTS
- **FR-017**: 不含任何可朗读内容的台词（如纯标点"？？？"）MUST 不生成音频文件，播放时 MUST 按"无本地音频"走回退路径；这类条目 MUST 在覆盖率校验中与"缺失"区分开，单独归类为已豁免

### Non-Functional Requirements

- **NFR-001**: 本地音频从触发到开始播放的延迟 MUST ≤ 200ms（不含系统音频设备启动时间）
- **NFR-002**: 单条音频文件 MUST ≤ 50KB（按平均 2～4 秒台词、低码率单声道估算），全量音频总体积 MUST ≤ 40MB
- **NFR-003**: 首次播放不得阻塞 UI 主线程超过 16ms
- **NFR-004**: 音频生成脚本对 1400+ 条台词的全量生成 MUST 支持断点续跑：中断后重跑不重复已有文件
- **NFR-005**: 应用在完全离线环境下 MUST 能正常播放所有已收录音频

### Key Entities

- **台词条目（Line）**：一句宠物会说的话。关键属性：稳定 id、显示文本、可选生成用文本、所属分组
- **台词分组（Dialogue Group）**：按触发场景划分的台词集合（宠物状态、天气、心情、属性提醒、问候语、梦话、日程等）。一个分组按顺序引用若干台词条目
- **音频资产（Audio Asset）**：某句台词在某个语音引擎/音色下的音频文件。与台词条目是多对一关系（一个条目在不同引擎下有多份），文件路径由引擎前缀与台词 id 决定
- **生成台账（Generation Ledger）**：记录文本到 id 的分配关系，以及哪些条目需要重新生成

## Success Criteria

- **SC-001**: 日常使用中听到的台词（宠物状态类 + 天气类 + 心情类）100% 有本地音频，不再触发 TTS 转换
- **SC-002**: 断网状态下，所有有音频的台词都能正常发声
- **SC-003**: 全项目台词文本重复率降为 0（同一句文本只存一处）
- **SC-004**: 新增一条台词后，维护者运行一条命令即可完成音频生成，无需手工指定文件名
- **SC-005**: 全量音频总体积不超过 40MB，应用安装包体积增长在可接受范围内
- **SC-006**: 其他使用者克隆仓库后运行应用即可听到预录语音，无需安装 Python、edge-tts 或任何额外依赖

## Clarifications

### Session 2026-11-11

- Q: 台词 id 用什么机制分配？ → A: 台账文件自动分配。仓库维护 `文本 → id` 映射，新增文本分配新 id，改文案视为新台词分配新 id，旧 id 保留不回收；源码里台词仍写成可读的字符串数组
- Q: 预录语音用哪个音色？ → A: 晓伊 `zh-CN-XiaoyiNeural`（目录名 `edge-tts@zh-CN-XiaoyiNeural`）
- Q: 气泡显示时长和语音时长怎么协调？ → A: 跟随音频时长，取 `max(3 秒, 音频实际时长)`；TTS 回退路径因无法预知时长，保持现有 3 秒行为
- Q: 现有的 Edge TTS 主进程引擎怎么处理？ → A: 彻底移除，包括 `electron/edgeTTS.js`、`electron/edgeTTS-ipc.js`、preload 相关接口、语音面板引擎切换；回退路径仅保留浏览器 TTS
- Q: 运行时怎么知道"这句台词有没有音频"？ → A: 生成脚本顺带产出静态音频清单并提交进仓库，运行时 O(1) 判断，不做网络/文件探测
- Q: 覆盖率校验挂在哪个环节？ → A: 警告不阻塞。未生成音频时控制台警告并在校验报告里列出，但不阻塞 `npm run build`；发版前人工跑一次校验
- Q: 引擎前缀放目录还是文件名？ → A: 目录级前缀，`public/audio/edge-tts@zh-CN-XiaoyiNeural/idle_001.mp3`
- Q: 生成脚本用什么语言写？ → A: Node 脚本 + npm script，与现有 `scripts/perf-sweep.mjs` 风格一致，不引入新依赖
- Q: 验收场景写"100ms 内开始播放"与 NFR-001 的"≤200ms"矛盾，以哪个为准？ → A: 统一为 ≤200ms（验收场景与 NFR 均取此值）
- Q: `effectsMap.ts` 里徽章展示用的"嘿嘿~""阿嚏!"（不发声）算不算需要收编的台词？ → A: 不算台词，不纳入台词体系；它们只做视觉展示
- Q: 无实际读音的条目（如"？？？"）要不要生成音频？ → A: 不生成；播放时走回退路径；覆盖率校验中单独归类为"已豁免"，与"缺失"区分开

## Out of Scope

- 不做音频的流式播放、边下载边播放
- 不做语音识别（STT）相关改动
- 不做台词内容的改写或润色（仅收编与结构化）
- 不做多语言支持
- 不实现同一台词的多情绪多版本音频（后续可选扩展）
- 不改造 LLM 实时回复的 TTS（LLM 回复无法预录，继续走 TTS 回退路径）
